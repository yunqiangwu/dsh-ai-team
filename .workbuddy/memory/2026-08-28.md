## dsh-ai-team 插件开发(从零到全部测试通过)

- 为 DeepSeek Harness (DSH) 开发了 `dsh-ai-team` 双面插件(host + client),模拟 AI 软件团队:git worktree 隔离工作空间 + 共享仓库分支协作 + 任务看板 + 代码审查门控合并。
- 关键参考:官方仓库 /tmp/dsh-ref 的 `packages/experimental/agent-team*` 与 npm 上的 `dsh-token-budget`(第三方独立打包范例)。
- 架构决策:TeamService 与 cordis 解耦(可单测);数据流走 session 事件 `ai-team/update` + 投影 `aiTeam`(last-write-wins 全量快照),避免 Typert RPC 代码生成;UI 注册到 `conversation.input.dock` 插槽。
- 8 个工具:team_create / team_add_member / team_list / team_status / task_assign / task_update / team_branch / code_review。
- 构建链:tsc(双 tsconfig:host nodenext + client react-jsx)→ tsdown(host ESM + client CJS 包 `window.__ModuleLoader__.load` banner/footer)。
- 测试:tests/test-integration.ts(16 项断言,全绿)+ tests/smoke-cordis.ts(真实 cordis Context 加载构建产物,4 项,全绿)。
- 踩坑:pnpm 11 配置移到 pnpm-workspace.yaml;全局 `allowBuilds` 占位符需在项目级 `allowBuilds: {esbuild: true}` 覆盖;cordis 卸载 API 是 `ctx.plugin()` 返回的 `fiber.dispose()`;defineTool 的 render 返回需 `type: 'text' as const`;client 产物不能 import 任何 @deepseek-ai 值(仅类型)。

## 代码评审:main vs master 两分支(用户误以为本地两分支是两人实现)

- 关键事实:**本地 `main` 与 `master` 内容几乎完全相同**(仅 package.json 元数据差异);真正代表"两个不同实现"的是远程的 `origin/main`(A 作者)与 `origin/master`(B 作者),35 文件改动 +3106/-1739。
- origin/main 取向:HTTP REST 轮询 UI + EventEmitter 推送 + 每团队 JSON + GitBackend 接口(可内存单测)+ 文档最全(README/LICENSE)。审查门禁弱(review 不产出 error → 几乎恒 approve)。
- origin/master 取向:DSH 原生 session 投影(`useProjection('aiTeam')`)+ `onChange` 订阅 + 单 teams.json 防抖 + roles.ts 提示词 + 完整审查生命周期(approve 合并入 base / request_changes 打回计轮次)。service.ts 偏胖(607 行)。
- 评分:master ≈ 89/100(胜出,生产级健壮性),main ≈ 80/100(更易读/可移植/文档好但功能松)。建议以 master 为基底吸收 main 的 config/types 拆分与 README 规范。
