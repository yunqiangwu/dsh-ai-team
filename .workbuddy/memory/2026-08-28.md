## dsh-autopilot 增加"邮件 + 问卷工单"人工确认通知闭环

在无人值守升级（needs-human）时把人叫来处理决策/密钥/问答。

**新增文件**：
- `src/notification.ts`：Mailer（Node 原生 net/tls 实现的轻量 SMTP client，零第三方依赖，支持 AUTH LOGIN + STARTTLS + 隐式 TLS，凭证走 env 引用+脱敏）+ TicketServer（node:http 本地工单端点，GET /ticket/:id 渲染表单、POST 提交回写）

**接入点**：
- `view.ts` 给 `EscalationView` 加 `notification` 块（status/mailTo/mailDelivered/ticketUrl/submitted/submittedAt/autoResumed/error）
- `escalate.ts` 的 `EscalationManager` 加 `notify` 钩子，escalate 时调用
- `service.ts`：initNotification() 建 Mailer+TicketServer，notifyEscalation() 发邮件，submitTicketAnswer() 驱动答复回写+autoResume 自动恢复循环
- `index.ts` Config 加 `notification` 块；`projection.ts` escalation schema 扩展 + stateVersion→2；cordis.patch.yml 加示例
- Web 面板 EscalationFeed 显示通知状态徽标 + 工单链接

**配置**：`notification.enabled/smtp{host,port,secure,startTls,userEnv,passEnv,fromEnv}/mailTo/ticket{host,port,publicBaseUrl}/autoResume`

**测试**：`tests/test-notification.ts` 5 个（mock SMTP 全握手 + TicketServer 表单/提交 + service 通知状态 + autoResume 闭环）

**质量门**：typecheck 0 error / lint 0 warning / build 成功 / 23 tests 全绿（新增 5 个）

**关键排错**：
- schemastery `ticket.port` min(1) 与默认 0（随机端口）冲突 → 改 min(0)
- Mailer secure:false 强制 STARTTLS 对无 TLS 内网/测试失败 → 加 startTls 可选开关
- lint 下划线前缀字段名 + `\-`/`\[\]` 不必要的转义 → 修正
- TicketServer 需 renderTicket 对未知 id 返回 null 才走 404
